# בוט כתוביות עברית (Zovex Sub)

userbot בטלגרם שמקבל סרטון בכל שפה ומחזיר **קובץ SRT בעברית ברמת אולפן**,
ואופציונלית גם וידאו עם כתוביות צרובות (עד 10 דקות, צריבה קלה ומהירה).

## איך זה עובד

| שלב | כלי | מה קורה |
|---|---|---|
| 1 | ffmpeg | חילוץ אודיו FLAC 16kHz מונו, וחיתוך לחלקים אם צריך |
| 2 | Groq `whisper-large-v3` | תמלול עם חותמות זמן ברמת סגמנט ומילה + סינון "המצאות" על שקט |
| 3 | Gemini + חיפוש Google | מעבר חקר: נושא, דוברים ומגדריהם, אל מי פונים, שמות, מונחים, אימות ציטוטים |
| 4 | Gemini | תרגום/עריכה בחלונות, עם מסמך החקר כקונטקסט — התאמה 1:1 לשורות המקור |
| 5 | Gemini | בקרת איכות על כל הכתוביות יחד: זכר/נקבה, עקביות מונחים, מספרים |
| 6 | — | בניית SRT: תזמונים ללא חפיפות, מהירות קריאה, פיצול שורות עברי |
| 7 | ffmpeg | צריבה אופציונלית: `preset veryfast`, CRF 28, thread אחד, עד 720p |

**למה הזכר/נקבה יוצא נכון:** ההחלטה מי הדובר ואל מי הוא פונה מתקבלת **פעם
אחת על כל הסרטון** במעבר החקר, ואחר כך כל שורה מתורגמת לפי ההחלטה הזו —
במקום שהמודל ינחש מחדש בכל שורה. מעבר הבקרה בסוף סורק את כל הכתוביות
יחד ומתקן התאמות מגדר שנשברו באמצע.

## התקנה על שרת לינוקס

```bash
# 1. תלויות מערכת (ffmpeg + פונט עברי לצריבה)
sudo apt update
sudo apt install -y ffmpeg python3-venv python3-pip fonts-noto-core
sudo apt install -y fonts-noto-hebrew || true   # לא קיים בכל ההפצות; fonts-noto-core מספיק
fc-cache -f
fc-list | grep -i hebrew | head -3              # לוודא שיש פונט עברי לצריבה

# 2. הקוד
sudo mkdir -p /opt/zovexsub && sudo chown "$USER" /opt/zovexsub
git clone -b ccr-7e9ba85e-p9u399 https://github.com/davidggjg/zovex-android /opt/zovexsub/repo
ln -s /opt/zovexsub/repo/bot /opt/zovexsub/bot

# 3. סביבה וירטואלית
python3 -m venv /opt/zovexsub/venv
/opt/zovexsub/venv/bin/pip install -r /opt/zovexsub/bot/requirements.txt

# 4. הגדרות — כאן נכנסים המפתחות (לא בגיט!)
cp /opt/zovexsub/bot/.env.example /opt/zovexsub/bot/.env
nano /opt/zovexsub/bot/.env
chmod 600 /opt/zovexsub/bot/.env

# 5. התחברות ראשונה לחשבון (מספר טלפון + קוד). מריצים פעם אחת באופן ידני:
cd /opt/zovexsub/bot && /opt/zovexsub/venv/bin/python -m zovexsub.bot
```

`TG_API_ID` ו-`TG_API_HASH` נלקחים מ-https://my.telegram.org ← API development tools.

### הרצה כשירות

```bash
sudo cp /opt/zovexsub/bot/zovexsub.service /etc/systemd/system/zovexsub.service
sudo sed -i "s/User=%i/User=$USER/" /etc/systemd/system/zovexsub.service
sudo systemctl daemon-reload
sudo systemctl enable --now zovexsub
sudo journalctl -u zovexsub -f
```

## שימוש

**סרטון לבד לא מפעיל כלום.** שולחים סרטון, ואז **מגיבים להודעה של הסרטון** עם `.srt`.

אפשר גם לשלוח קישור במקום קובץ: `.srt https://...` — הבוט מוריד את הווידאו
בעצמו דרך yt-dlp (יוטיוב, videa.hu ומאות אתרים אחרים), ומעלה את התוצאה
לטלגרם. אותן סטטיסטיקות התקדמות בכל השלבים.

הבוט מתמלל, שולח את קובץ ה-SRT, ואז — **רק אם הסרטון קצר מ-10 דקות** —
שולח הודעה נפרדת: "רוצה שאצרוב את הכתוביות על הסרטון?". מי שרוצה משיב
לה `כן`, ורק אז הצריבה מתחילה. **אין צריבה אוטומטית**, גם לסרטון קצר.

סרטון מעל 10 דקות: נשלח SRT, ובמקום ההצעה נשלחת הודעה שצריבה לא זמינה באורך הזה.

הצעת צריבה שלא נענתה תוך חצי שעה פגה, והקבצים הזמניים נמחקים מהשרת.

רק משתמשים ברשימת המורשים (ואתה) יכולים להפעיל. מי שלא מאושר — הבוט מתעלם ממנו לגמרי.

## ניהול מורשים (רק מהחשבון שלך, נוח בהודעות השמורות)

| פקודה | מה היא עושה |
|---|---|
| `.srt id` בתגובה להודעה של מישהו | מראה שם + **ID** + האם הוא מאושר |
| `.srt הוסף` בתגובה להודעה | מאשר את מי ששלח אותה |
| `.srt הוסף 123456789` | מאשר לפי ID |
| `.srt הסר 123456789` / `.srt הסר` בתגובה | מבטל אישור |
| `.srt רשימה` | כל המאושרים |
| `.srt ניהול` | כל פקודות הניהול |

**הדרך הקלה להוסיף מישהו:** מעבירים (Forward) הודעה שלו להודעות השמורות, ומגיבים לה
`.srt הוסף`. הבוט מחזיר את השם וה-ID ומוסיף אותו.

הרשימה נשמרת ב-`allowlist.json` ליד הקוד — לא צריך לערוך `.env` ולא להפעיל מחדש.

### בדיקה בלי טלגרם

```bash
cd /opt/zovexsub/bot
/opt/zovexsub/venv/bin/python cli.py /path/to/video.mp4 --burn
```

## שליטה בעומס השרת

הכול ב-`.env`:

| משתנה | ברירת מחדל | מה זה עושה |
|---|---|---|
| `BURN_MAX_MINUTES` | 10 | מעל זה נשלח SRT בלבד, בלי צריבה |
| `BURN_TIMEOUT` | 1800 | תקרת זמן קשיחה לצריבה בשניות |
| `BURN_THREADS` | 2 | ליבות לצריבה |
| `FFMPEG_THREADS` | 1 | ליבות לחילוץ אודיו וזיהוי דיבור |
| `BURN_PRESET` / `BURN_CRF` | veryfast / 28 | איכות מול מהירות |
| `BURN_MAX_HEIGHT` | 720 | הקטנת רזולוציה לפני צריבה |
| `NICE` | 15 | עדיפות CPU נמוכה (+ `ionice -c 3`) |
| `MAX_INPUT_MINUTES` | 180 | אורך מקסימלי לתמלול |
| `DISK_FACTOR` / `DISK_RESERVE_GB` | 2.5 / 3 | כמה מקום פנוי נדרש לפני שמתחילים |

בנוסף: **שני תורים נפרדים** — צריבה ארוכה לא חוסמת בקשת כתוביות קצרה;
`systemd` מגביל זיכרון ל-3GB ועדיפות IO ל-idle.

### מה זה באמת עולה

נמדד על מכונת 4 ליבות, מקור 1080p גרעיני (המקרה הקשה), יעד 720p עם
כתוביות צרובות:

| threads | מהירות | שעתיים וחצי וידאו | גודל פלט |
|---|---|---|---|
| 1 | 0.71x | 3.5 שעות | זהה |
| **2** | **1.68x** | **1.5 שעות** | זהה |
| 4 | 2.52x | שעה | זהה |

מספר ה-threads לא משנה את גודל הפלט או את האיכות — רק את משך החלון. על
תוכן דיגיטלי נקי המהירות גבוהה פי שלושה בערך.

שינוי `preset` או רזולוציה כמעט לא עוזר על תוכן גרעיני (0.71x מול 0.95x
בין veryfast 720p ל-ultrafast 480p), כי הצוואר הוא פענוח המקור ולא
הקידוד. `ultrafast` גם מכפיל את גודל הפלט, מה שמייקר את ההעלאה.

חילוץ האודיו וזיהוי הדיבור זניחים (פי מאה מהזמן אמיתי), והתמלול והתרגום
רצים אצל Groq ו-Google ולא על השרת.

## מהירות מול טלגרם

שני צווארי בקבוק טופלו כאן.

**הצפנה.** כל בייט שעובר מול טלגרם מוצפן ב-AES. בלי החבילה `cryptg` זה
נעשה בפייתון טהור. נמדד על מכונה זו:

| מימוש | קצב |
|---|---|
| פייתון טהור | 0.4MB/שנייה |
| `cryptg` (קוד C) | 68MB/שנייה |

פי 170. בלי `cryptg`, קובץ של 686MB מבזבז כ-28 דקות על פענוח בלבד, בלי
קשר למהירות הרשת. החבילה נמצאת ב-`requirements.txt`, והבוט מתריע בלוג אם
היא חסרה.

**סדרתיות.** טלתון מבקש חלק, ממתין, מבקש את הבא. `TG_CONNECTIONS`
(ברירת מחדל 4) מריץ כמה בקשות במקביל בשני הכיוונים. אם המסלול המהיר
נכשל מכל סיבה, המערכת נופלת חזרה למימוש הרגיל של טלתון.

## מפתחות API

`GROQ_API_KEYS` ו-`GEMINI_API_KEYS` מקבלים **כמה מפתחות מופרדים בפסיק**.
המערכת מסובבת ביניהם (round-robin), ומפתח שחוזר עם 429 נכנס לקירור
אוטומטי ולא נבחר עד שהוא משתחרר. אפשר להוסיף או להסיר מפתחות בכל שלב —
רק `.env` ואתחול השירות.

⚠️ מפתחות נשמרים **רק** ב-`.env`, שנמצא ב-`.gitignore`. מפתח שנחשף — החליפו אותו.
